# 引用修改

使用前查询安装版本的 schema。旧版未提供这些命令时，不能把文档中的命令当作已安装能力；也不要将项目 Python COM 脚本包装成已有 CLI 接口。
若 schema 不支持，先取得包含该功能的已验证版本，再继续依赖该接口的步骤。

## 操作入口

```powershell
cat5cli schema product component replace
cat5cli schema drawing source set
```

两类操作都修改 CATIA 会话中的文档，保存另用 `document save --file-path <路径>`。`document save-as` 使用 CATIA 原生另存；宿主文件工具改名是另一条需要处理引用的路线。FullName 是读取路径，不是可写的重定向接口。

## 组件引用

- 使用 `product tree` 的零基 node 定位组件，根为 `0`；根不能作为被替换组件。
- 默认修改选中组件定义。共享子装配中的定义会影响该子装配的多个出现路径；“未指定全部实例”不代表只影响一个可见出现。
- `--all-instances` 表示向 CATIA 请求替换相同引用的实例，不表示工具已经核验全树；按每条需要修改的引用读回，尤其是原引用已断链时。
- 嵌套组件实际修改的可能是子装配文件，保存所属子装配，而不只是顶层总装。
- 替换之后重新读取定位和实际文件路径，不能假定实例名、顺序、约束或全部关联一定保持不变。

## 图纸源

- `drawing info` 查询页、视图及生成源；对明确的生成视图操作，背景视图不是生成视图。
- 新的 CATPart/CATProduct 先用 `document open` 打开，再传给源重绑命令；不把任意零件中的 Body/面当成整文档源。
- 源重绑与更新不是复杂尺寸、上下文外链及图框文本的自动迁移保证。逐图检查实际来源、更新状态和尺寸关联。
- PDF 中的文字不会随文件名改变；修改并保存图纸后再用 `drawing export pdf` 生成新 PDF。
- 图号可能位于图框表格单元格，而不在普通 DrawingText 中。应同时检查文本、表格和实际关联参数；导出后抽取 PDF 文字检查旧编号，并核对页数。当前 CLI 没有专用表格批改命令，不能凭空编造参数。

## 单文件改名：原生 SaveAs

已有引用有效时，优先使用原生另存流程；不先用文件系统改名制造断链。现有命令足以组合此操作，无须项目专用迁移命令。

1. 明确目标零件及本批父装配、图纸，先全部打开并读取实际引用。`document dependencies reverse` 只检查当前已打开的 CATProduct/CATDrawing，不代表全磁盘引用方，也不覆盖所有 CATPart 上下文外链。
2. 检查新路径冲突，记录未保存修改的处理方式及改名前基线。文件名与 PartNumber 分开处理；本流程不自动改 PN、实例名或图框文字。
3. 对目标执行 `document save-as --doc <旧文档完整路径> --file-path <新文件完整路径>`。它保留旧文件；不是删除旧路径的文件系统重命名。
4. 读回目标及各引用方的实际链接，然后对明确的引用方逐个执行 `document save --file-path <引用方完整路径>`，即使其 Saved 为 true。不要用全会话 SaveAll 代替明确范围；只保存顶层总装也不等于保存所属子装配。
5. 关闭本批显式打开的父装配、图纸和目标，重新打开引用方核验实际新路径、位置、约束及图纸关联。不要预先加载新零件来掩盖磁盘上的断链。共享文件只改一次，每个父引用分别验收。
6. 文件生成、引用更新、引用方保存、冷重开核验分别记录。失败或等待时接续原 task，不能重新执行已经成功的 SaveAs。旧文件是否清理须另行决定；未打开且未处理的引用方仍可能依赖旧文件。

复杂外链、关联尺寸及不可读字段需要单独验收；一次成功的路径读回不能证明这些内容全部保持不变。

### 多版本目录的分批边界

- 主设计和历史交付副本可能同名、同内部标识，CATIA 可能复用另一目录已加载的文档。每次打开都比较请求路径与返回 FullName；不一致即停止该批写入。
- 按独立版本分批，关闭并确认上一批已卸载，再打开下一批；仅改变待处理文件列表不足以清除旧会话对象。批次不能把仍需同步的父引用遗漏在外。
- 来源不明的 STEP/PDF 不能只按文件名选一个 CAD 版本重新导出。记录来源歧义；STEP 导入再导出也可能产生几何数值变化，必须事先确定验收精度，不能为通过检查临时放宽阈值。

## 文件系统改名与重连（另一条路线）

1. 改名前保存旧路径→新路径，以及父文档、组件 node、原引用路径。改名后 ReferenceProduct 可能不可读，不能届时才建立映射。
2. 检查新目标已存在和多个旧名映射同一新名两种冲突。供应商内容不修改，但父目录改名可能使供应商路径变化。
3. 明确本批文档已有未保存修改的保留方式；需要保留的先显式保存并核实。未保存文档先用 document save-as 落盘，不静默丢弃修改。关闭涉及的文档后由宿主改文件/目录名，按依赖自底向上重新打开和重连。
4. 一级子装配逐批处理，共享文件只处理一次，每个父引用分别检查。总装最后单独处理直接引用，不从总装重复采集和编辑整机 BOM。
5. 修改成功与保存成功分别记录；失败后核对原任务及已生效修改，不从头重复整批。

清单按每个父引用记录父文件、原 node、旧路径、预期新路径、读回新路径、所属修改文档和保存结果。无法读取或无法对应的项保留为未完成；不能据一次成功结果把清单剩余项批量标为完成。

`running`、`waiting_for_dialog`、`busy` 按 [执行与任务接续](execution.md) 处理。项目规则和进度清单由宿主维护，cat5cli 提供通用操作，不负责一键项目迁移。

## 文件警告与批处理状态

- CATIA `Application.DisplayFileAlerts=False` 控制文件警告，不能视为关闭所有弹窗、修复断链或确认所有业务操作。许可、恢复及普通错误提示没有统一抑制保证。
- 这是 CATIA 会话级 COM 属性，不是现有 CLI 的同名参数。使用经确认的脚本设置时，读取原值，在最小操作范围内修改，并在 `finally` 恢复；进程被强制结束时 `finally` 不会可靠执行，需单独核对状态。
- `RefreshDisplay` 控制显示刷新，`HSOSynchronized` 控制选择高亮同步，`Interactive` 控制用户交互响应，均不能冒充文件警告开关。不要为了处理保存提示随意修改这些属性。
- 分别记录打开、读取、另存、保存引用方、关闭的耗时。抑制提示不代表文件读写或链接解析一定更快。
- 文档 `Close()` 返回不等于文档已从会话卸载：它可能仍被其他已打开装配引用。先关闭明确打开的顶层引用方，再检查剩余对象；重复调用未取得进展就停止并报告，不能无限关闭同一引用文档。
- 既有断链与本次目标引用分开记录。目标引用必须读回验证；其他既有不可读字段属于验收范围限制，不能宣称已验证，也不应自动扩大成修复整个历史装配的任务。
