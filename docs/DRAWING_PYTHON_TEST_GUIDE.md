## 测试步骤

### 测试 1：新建图纸功能对比

#### 准备工作
1. 启动 CATIA V5 R28
2. 打开一个 CATPart 文件（确保有 PartNumber、Nomenclature、Revision 等属性）
3. 准备一个图纸模板（放在 `drawing_templates/` 目录）

#### 测试 VBScript 版本（基准）
1. 点击 **"新建图纸 (VBScript)"**
2. 选择模板
3. 观察：
   - 是否成功创建图纸
   - 是否弹出 CATIA 原生 InputBox（如果属性缺失）
   - 是否弹出 CATIA 原生 MsgBox 显示同步日志
   - 记录同步的属性值

#### 测试 Python 版本（新实现）
1. 关闭刚才创建的图纸（不保存）
2. 点击 **"新建图纸 (Python)"**
3. 选择相同的模板
4. 观察：
   - 是否成功创建图纸
   - 是否弹出 Qt InputDialog（如果属性缺失）
   - 是否弹出 Qt MessageBox 显示同步日志
   - 对比同步的属性值是否与 VBScript 版本一致

#### 预期结果
- ✅ 两个版本创建的图纸参数应该完全一致
- ✅ Python 版本的对话框风格更现代（Qt 风格 vs CATIA 原生风格）
- ✅ Python 版本的日志信息更详细

---

### 测试 2：刷新图纸功能对比

#### 准备工作
1. 使用测试 1 创建的图纸（或打开一个已有的 CATDrawing）
2. 确保对应的 CATPart 已在 CATIA 中打开
3. 修改 CATPart 的某个属性（如 Nomenclature 或自定义属性"材料"）

#### 测试 VBScript 版本（基准）
1. 激活图纸文档
2. 点击 **"刷新图纸 (VBScript)"**
3. 观察：
   - 是否成功找到对应的零件
   - 是否更新了图纸参数
   - 记录更新后的属性值

#### 测试 Python 版本（新实现）
1. 再次修改 CATPart 的属性（改为不同的值）
2. 激活图纸文档
3. 点击 **"刷新图纸 (Python)"**
4. 观察：
   - 是否成功找到对应的零件
   - 是否更新了图纸参数
   - 对比更新后的属性值是否正确

#### 预期结果
- ✅ 两个版本都能正确找到对应的零件
- ✅ 两个版本都能正确更新图纸参数
- ✅ Python 版本的错误提示更友好

---

### 测试 3：边界情况测试

#### 测试 3.1：零件缺少属性
1. 打开一个没有自定义属性的 CATPart
2. 分别用两个版本创建图纸
3. 观察：
   - VBScript 版本：弹出 CATIA InputBox
   - Python 版本：弹出 Qt InputDialog
   - 输入的值是否正确写入零件和图纸

#### 测试 3.2：图纸模板缺少参数
1. 使用一个不包含 "物料编码" 参数的模板
2. 分别用两个版本创建图纸
3. 观察：
   - 两个版本是否都能正常处理（跳过缺失的参数）
   - 日志中是否有相应提示

#### 测试 3.3：错误的文档类型
1. 激活一个 CATProduct（不是 CATPart）
2. 点击 **"新建图纸 (Python)"**
3. 观察：
   - 是否显示友好的错误提示
   - 错误信息是否清晰

#### 测试 3.4：找不到对应零件
1. 打开一个图纸，但不打开对应的 CATPart
2. 点击 **"刷新图纸 (Python)"**
3. 观察：
   - 是否显示友好的错误提示
   - 错误信息是否包含零件编号

## 已知差异

### 1. 对话框风格
- **VBScript**：CATIA 原生对话框（Windows 98 风格）
- **Python**：Qt 对话框（现代扁平化风格）

### 2. 日志详细程度
- **VBScript**：简单的成功/失败信息
- **Python**：详细的操作步骤和结果

### 3. 错误处理
- **VBScript**：通用错误提示
- **Python**：具体的错误原因和解决建议
