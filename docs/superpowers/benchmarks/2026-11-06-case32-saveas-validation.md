## 实测发现

1. 主设计与 gear 历史副本同会话加载时，CATIA 会复用另一目录的同名/同内部身份文档。最初混合加载失败在修改前；随后增加每次 Open 的 FullName 校验，并隔离为五批。仅改变文件列表而不卸载上一批不能解决该问题。
2. 普通 DrawingText 替换不覆盖图框表格。首轮 88 个 PDF 均能打开且页数与旧版一致，但抽取文字仍有旧图号。已定位到 DrawingTable 的单元格，例如首张图的主视图表格 2、行 1、列 5。
3. 多页 PDF 导出设置可能生成逐图纸文件，而非请求的单个文件。`ASY_VE01-32200-000` 的两页已找到，合并后页数与旧 PDF 同为 2；不能仅因目标文件名未出现就断言未导出。
4. 34 个 STEP 按文件名能匹配多个 CAD 版本，不能随意选择一个重导出。尝试从原 STEP 自身导入后改号：`Documents.Open` 返回的临时 STEP 对象无 Product；真正的 CATPart 需从 Documents 重新定位。
5. 单件 STEP 往返样本的质量从 `0.008247103752770223` 变为 `0.008247067149584751`，相对差约 4.44 ppm。树结构和新编号正确，但未通过原先 `max(1e-9, abs(mass)*1e-7)` 的质量阈值。其余 33 个未继续；未为通过验收临时放宽精度。

## 验证边界

- 本轮批量 CAD 检查覆盖直接产品引用路径、图纸生成源及既有不可读项变化，不等同于逐文件几何、装配位置、约束、尺寸关联的全面验收。
- 原有断链没有自动扩大为修复任务。旧文件保留，未操作的外部引用仍可能依赖它们。
- 主批处理通过临时 Python COM 脚本执行，以验证方法与耗时；不是新发布的批处理 CLI 命令。未构建、发布或安装新版本。
- 所有本轮脚本均由主会话亲自执行；没有再委托子 agent 操作 CATIA。
