# BOM 子装配实例改名修复

## 复现与根因

- 自建 sub.CATProduct 包含一个子实例，顶层装配重复引用该文件两次。
- 原始 COM：对顶层出现路径 `parent.Products.Item(1).Name` 赋值不抛异常，但回读仍为旧值。
- 写 `parent.ReferenceProduct.Products.Item(1).Name` 后，子装配源文档和两条出现路径均回读为新值。
- 旧正式EXE实机回归复现：两次嵌套改名均返回success，第二次old_value仍是初始名称，确认并非单纯BOM显示缓存。

## 修复边界

- 仅CLI的instance编辑分支改为写父级引用定义中的实例对象，保留现有write_cell及GUI行为。
- 每项重新解析出现路径，旧名称不依赖先前采集缓存；写入前严格读取并比较引用PartNumber和FullName，读取失败即停止该项，不能使用空值容错证明对象一致。
- 写入后重新从根沿node路径回读Name，只有与请求一致才成功；结果增加observed_value。回读不符或失败不计入applied_count，不声称回滚，后续独立项继续。
- 同一子装配定义的多条出现路径可能联动，符合既有约定；根层两个独立实例名不互相影响。
- 主数据编辑和DescriptionInst只读边界保持不变。

## 验证

- 新增/强化回归覆盖嵌套静默setter、真实writer根层定位、回读不符及异常、定义不匹配/身份不可读、旧值刷新。
